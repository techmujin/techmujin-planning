## 1. トラック設計

### 1-1. 会場の物理前提

治ホールは**平土間**で、椅子・机を自由にレイアウトできる。設計を決めるのは次の2点。

- **ホール本体は音を出せる空間として専有できる。** 平土間なので「ステージ＋客席」の島を必要な大きさだけ作れ、余った面積を別用途に回せる。
- **ホール以外のスペース（ホワイエ・隣室）を借りられるかで構成が変わる。** 借用可を前提に設計する（**本日の定例会で大学へ確認する事項**）。

ホール外を使えれば、**ブースと作業スペースを音の出るステージから物理的に切り離せる**。ブースでの会話品質・ハッカソンの集中と、ステージの音量を両立できる。

### 1-2. 2パターンの構え

| | パターンA（基本方針） | パターンB（ホール単一の場合） |
|---|---|---|
| 前提 | ホール外スペースを借用できる | 治ホールのみ |
| T1 ステージ | ホール前方（客席100席想定） | ホール前方（客席80席程度に縮小） |
| T2 ブース | **ホール外（ホワイエ等）に常設** | ホール後方・外周に配置 |
| T3 作業スペース | **ホール外（ブース隣接）に終日常設** | ホール後方に作業島。客席と兼用も可 |
| 音の扱い | ブースの会話とハッカソンの作業がステージ音に干渉しない | ステージ音量を「後方で会話が成立するレベル」に抑える必要がある |

**A で設計を進め、借用不可が判明した時点で B に畳む。** タイムテーブル（§2）は A・B どちらでも成立する構成にしてある（差分は T2・T3 の位置と音量運用だけ）。

### 1-3. トラックへの割り当て

| トラック | 性質 | 割り当てるコンテンツ |
|---------|------|---------------------|
| **T1 ステージ（発表）** | 時間割・増幅音声あり・全体の軸 | C1 / C7（お題発表・結果発表）/ C2 / C4 / C3＋N7 / C6（クロージング）＋演出 N4・N5、運用 N6 |
| **T2 ブース（展示・頒布・体験）** | 常設ゾーン | C5 / N1 物販 / N2 make工作 / N3 合同誌その場執筆 |
| **T3 作業スペース（ハッカソン）** | 終日常設・出入り自由 | C7 生成AI活用型ハッカソンの制作時間 |

設計の肝:

- **ステージは「誰が話すか」で進む。** 主催が話す（C1）→ コミュニティが話す（C2・C4）→ 参加者が話す（C3・N7）。後半にいくほど場の主役が客席側へ移り、初参加者が「自分も関わってよい」と感じられる順序にしている。
- **コミュニティ紹介（C2）がイベントの主コンテンツ。** テック無尽の目的は横のつながりの創出であり、その入口は「どんなコミュニティがあるか」を知ること。**1コミュニティ5分を死守**し、他のコンテンツの枠をここに合わせて調整する（§2-1）。
- **ハッカソン（C7）は終日並走。** お題をオリエンテーション直後に出すことで、参加者は昼休憩・セッションの合間・ブースを回りながらなど、**自分のペースで制作時間を確保できる**。Webアプリ経由の非同期参加なので、T3 に張り付かなくても客席やブースから参加できる。
- **代読LT（C3）とラジオ（N7）は連続した1ブロック。** どちらも「参加者・関係者の声を拾う」という同じ狙いで、C3 が参加者から緩く広く募る側、N7 がコミュニティ関係者をゲスト化して深堀りする側。投稿フォームと司会を共有し、**C3 で拾った話題をそのままラジオのゲストに振る**ことでシームレスにつなぐ。
- 演出・運用（N4・N5・N6）はステージ付帯機能として T1 に内包。
- 結果発表・クロージングの頃には **T2・T3 は撤収開始**。全員が T1 に集まる導線にして自然に締める。

### 1-4. 規模の目安（100名前提）

- T1 客席: 100席（平土間なので椅子のみ／後方に立ち見スペース）。パターンBでは作業島に面積を割くため80席程度。
- T2 ブース: 参加コミュニティ11＋協賛・個人を見込み、**10〜14ブース**（1ブース＝長机1本）。
- T3 作業スペース: 島型に机を並べ **24〜32席**（同時に着席するのは参加者の1/4〜1/3という想定。終日常設だが全員分は不要）。
- **治ホールの収容人数・電源容量・机椅子の備品数は未確認**（§5 確認事項）。上記が入らない場合は T2 のブース数から削る。

### 2-1. 枠設計

**C2 は 1枠5分＋転換1分＝6分/枠を死守する。** 他コンテンツはこれに合わせて調整する。

| コンテンツ | 1枠 | 枠数 | 所要 |
|---|---|---|---|
| **C2 コミュニティ紹介** | **6分（発表5分＋転換1分）** | 11（全参加コミュニティ） | 66分＋予備4分＝**70分** |
| C4 コミュニティLT | 7分（発表5分＋転換2分） | 10（手挙げ制） | **70分** |
| C3 代読LT | — | — | **20分**（N7 と連続） |
| N7 ラジオ | — | ゲスト3〜4組 | **60分**（C3 と合わせて80分ブロック） |
| C7 ハッカソン | — | — | お題発表**10分**／結果発表**20分**（制作時間はステージの時間割の外） |

- スライドは事前提出＋一括投影とし、**登壇者の入れ替わりだけで転換1分**に収める運用にする。C2 は11組が連続で登壇するため、ここのオペレーションが崩れると全体が押す。
- **調整中3コミュニティが加わり14になった場合**、C2 は 14×6分＝84分。不足する14分は **C4 コミュニティLT を70分→56分（10枠→8枠）に縮小して捻出する**。C4 は手挙げ制で枠数を調整しやすく、かつ「コミュニティ紹介に比重を置く」方針とも一貫する。
- **C4 は手挙げ制**とし、応募多数の場合は先着または抽選。C2 で全コミュニティに登壇機会があるため、C4 を絞っても不公平にはならない。この方針を**コミュニティ連携トラックから各コミュニティへ明示的に伝える**必要がある。

## 3. コンテンツの説明

### T1 ステージ（発表）

- **C1 オリエンテーション・場づくり** … MC が趣旨と進め方を説明。「聞くだけ参加も歓迎」「自由に回遊してよい」を明示し、初参加者の心理的ハードルを下げて場の空気を整える。この直後にハッカソンのお題発表が続くため、**1日の過ごし方の選択肢を提示する場**でもある。
- **C7 ハッカソン お題・レギュレーション発表** … お題・制約・提出方法・締切（16:00）・審査方法を発表する。**早い時間に出すことが要点**で、参加者はこの後の昼休憩やセッションの合間を制作に充てられる。「聞くだけ」「作るだけ」「両方」のどれでもよいことを明言する。
- **C2 コミュニティ紹介** … 参加する全コミュニティの運営メンバーが登壇し、活動内容や雰囲気を **1枠5分**で紹介。技術的な詳細より「どんな人がいて、どんな空気で活動しているか」を重視し、参加者が「自分が参加した場合のイメージ」を持てるようにする。**本イベントの主コンテンツ**であり、後半の会話・ブース訪問の共通の話題を作る土台になる。
- **C4 コミュニティLT** … 手挙げ制10枠のライトニングトーク。C2 が「コミュニティの紹介」であるのに対し、C4 は「そのコミュニティが取り組んでいるテーマの中身」に一歩踏み込む枠と位置づける。
- **C3 代読LT（参加者の反応を拾う）** … 受付で配布する QR から、参加者がスマホで「来た理由」「気になる技術」「聞いてみたいこと」などを投稿。司会がその場でピックアップして代読し、発言が苦手でも一歩関われる体験を提供する。**このまま N7 ラジオへ連続して移行する。**
- **N7 テック無尽ラジオ（公開トークコーナー）** … 主催＋ラジオパーソナリティ担当が、C2・C4 の登壇者やコミュニティ代表をゲストに招き、活動や発表内容を深堀りする公開トーク。C3 で集まった投稿を「お便り」として紹介し、ゲストが答える形で進める。**C3 が参加者の声を緩く広く拾う側、N7 がそれをコミュニティ側に投げ返して深める側**という関係で、投稿フォーム・司会・進行を共有する。匿名／ハンドルネームでの投稿を可とし、「前に出て話す」ハードルをさらに下げる。
- **C7 ハッカソン 結果発表・人気投票** … 提出作品を紹介し、参加者投票で人気作を決める。作った人が壇上で一言話す時間を取り、ここでも「参加者が話す」流れを維持する。
- **C6 クロージング** … まとめと各コミュニティの今後のイベント情報・参加方法の案内。その場限りで終わらない関係性につなげる。

### T2 ブース（展示・頒布・体験）

パターンAではホール外（ホワイエ等）、パターンBではホール後方・外周に展開する。

- **C5 オープンブース・交流エリア** … テーブルを配置し、コミュニティ・個人・協賛企業が出展。「見るだけ」「立ち寄るだけ」も歓迎し、会話が苦手な人の居場所を作る。事前エントリー制。
- **N1 物販・頒布コーナー** … 技術書典／コミケ的な頒布。出展者の継続的な活動につながる。大学施設での物販可否は**要確認**（§5）。
- **N2 make・工作コーナー** … 手を動かす体験型コーナー。電源・工具の使用可否を会場条件とあわせて確認する。
- **N3 合同誌 その場執筆** … コミュニティ合同誌のページを当日その場で執筆（絵・一言感想も可）。技術書典など後続イベントへの接続を狙う。

### T3 作業スペース（ハッカソン）

- **C7 生成AI活用型ハッカソン（制作時間）** … 11:15 のお題発表から 16:00 の提出締切まで**終日開放**。ステージの時間割に縛られず、参加者が自分のペースで制作する。Webアプリ経由の非同期参加で、発言せずに参加でき技術レベルを問わない。T3 に着席しなくても客席・ブースから参加できるが、**メンターが常駐する相談窓口**として T3 を置く（昼休憩帯に厚く配置）。会場 Wi-Fi と電源の確保が前提条件（§5）。

### 演出・運用（T1 付帯）

- **N4 Claude Code ライブスライド** … 代読LT（C3）のコメントをその場でスライド化する演出。ラジオ（N7）のお便り紹介にも流用する。
- **N5 ニコニコ風 弾幕表示** … 代読LT（C3）のコメントを画面に弾幕で流す演出。C3〜N7 のブロックを通して稼働させる。
- **N6 LT資料 QRコードDL** … C2・C4 の資料を QR でいつでもダウンロード可にし、今後の参加につなげる運用改善。

## 4. 取り切り担当（コンテンツオーナー）

コンテンツ設計トラックが全体の枠組みを引くが、**個々のコンテンツを当日成立するところまで持っていく責任者（＝取り切り担当）を1人ずつ決める**。ここが決まらないと Phase 3（コンテンツ詳細の確定）が閉じない。

### 4-1. 「取り切り」の責任範囲

取り切り担当は、担当コンテンツについて次を負う。

- **設計**: 進行台本・所要時間・必要な事前準備の確定
- **調達**: 登壇者・出展者・機材・ツールの手配（他トラックへの依頼を含む）
- **当日運営**: 進行、またはその日の進行役への引き継ぎ
- **判断**: 中止・縮小・時間変更が必要になったときの一次判断と、実行委員長へのエスカレーション

担当は「自分ひとりで作業する人」ではなく、**必要な人を巻き込んで完了させる責任を持つ人**。作業の分担は自由。

## 5. 未確定事項（本日の定例会で確認・決定したいこと）

1. **ホール以外のスペース（ホワイエ・隣室）を借りられるか** … パターンA／Bの分岐。最重要。
